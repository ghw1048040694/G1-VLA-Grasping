# G1 VLA Grasping

G1 is being rebuilt as a fixed-stance, strict-contact manipulation system. There is one active configuration and one package entry point. The current stage trains a privileged state-based RL teacher in a separately versioned PhysX model. ACT and world-model optimization remain disabled. Existing source-native ACT results, data and the MuJoCo teacher remain separate research evidence.

## Privileged RL teacher

Run from WSL using the same configuration and entry point. The dispatcher freezes project sources, asset hashes and configuration, then reuses the installed native Windows Isaac runtime. It does not modify IsaacLab or launch legacy experiment scripts.

```sh
python -m g1_vla.cli experiment --config configs/experiment.json --stage rl-audit
python -m g1_vla.cli experiment --config configs/experiment.json --stage rl-smoke
python -m g1_vla.cli experiment --config configs/experiment.json --stage rl-train
python -m g1_vla.cli experiment --config configs/experiment.json --stage rl-eval
python -m g1_vla.cli experiment --config configs/experiment.json --stage rl-diagnose
```

`rl-smoke` checks the configured increasing parallelism without an optimizer, currently one, eight, thirty-two, 128 and 256 environments. It records device and system memory and stops on resource pressure. The capacity protocol supports up to 512 environments; the central configuration currently targets 256 after native host-memory measurements. The single-environment contact path must also complete a same-step, nonzero-contact crosscheck against the independent hand sensors. Every profile must report available qualification data and a positive measured Cube–Table load witness. Physics v3 represents the fixed table as an immovable kinematic rigid body so the native GPU pair filter can measure it; the earlier static-table filter was unsupported. Missing contact data stops the run before an optimizer step. `rl-train` requires a passed smoke report for the identical frozen release, then runs at most 400 PPO updates or 3600 seconds, including validation. At 256 environments and 32 rollout steps, the training ceiling is 3,276,800 transitions and 6400 optimizer calls; actual progress is always reported. The initial task uses Unitree's official fixed-base G1 29DOF + two Dex3 hands (43 joints), an 81-dimensional privileged observation and 14 right-arm/hand target increments. The known layout-15 open-hand joint fixture supplies a curriculum seed; model differences are declared and are not new independent demonstration data. Source control limits, the 2ms physics timestep and 33-step command cadence remain explicit. Other joints are held.

The native USD geometry, collision shapes, inertias and existing fixed root are pinned with their complete dependencies and official source revision. TGS, material combination, task PD and effort bounds are explicit overrides; this does not silently copy the official teleoperation configuration's enlarged hand torque limits. Its model identity differs from MuJoCo and the failed MJCF conversion candidate. The 6mm probe shield remains active throughout; actual overshoot is checked at 2ms intervals and fails the episode at the next 66ms control boundary. Local support qualification requires the original load/contact/stability AND gates and raw evidence; missing contact capability cannot count as success. This stage does not authorize a main lift or count as the original home-start 15/19 or twenty-layout acceptance.

Training preserves optimizer losses, gradients, weight changes, episode failures and immutable checkpoints. Deterministic evaluation retains a measured-joint state-hold request through the same command limits and the step-zero policy, with eight fixed validation offsets and equal episode quotas. Zero normalized velocity in this policy instead holds the previous target; the two controls are labeled separately. Incomplete quotas have no overall success rate. `rl-eval` requires an explicit checkpoint path and full SHA256 and verifies source, task and native model identities. No ACT test payload or legacy checkpoint is exported or used for selection. Exporting future ACT labels requires a separate reviewed action/timing bridge.

At 256 environments, each 32-step rollout supplies 8192 state-action transitions, rather than 8192 complete grasp episodes. The current reset varies the cube by only ±0.2mm in XY and ±0.001rad in yaw around one pregrasp seed. Observations include privileged object pose and palm-relative geometry, so the policy can condition its actions on object position; actual position adaptation still requires measured trajectory and success comparisons. More parallel environments do not enlarge this reset distribution. Centimeter-scale table variation and a complete approach from a safe open-hand start require a separately versioned curriculum, collision and reachability checks, and held-out position evaluation. Camera-based and multi-object generalization remain separate milestones.

`rl-diagnose` runs the explicit `rl_diagnostics` control protocol with no optimizer or backward pass. It pins the completed update-78 actor, its original release/source/configuration and full normalization state. Modified controls are labeled as frozen-actor counterfactuals; the existing `rl-eval` identity checks remain strict. The original `four_way_v1` comparisons reuse the same eight environments and fixed offsets, with four scored episodes per offset: original scalar guard, box/height projection guard, guided finger closure with actor arm commands, and guided closure with palm-pose control. Its original guided closure replays an unqualified source target. The current `compliant_pinch_v4` plan uses the separately declared force-feedback controller described below. Both remain diagnostic interventions, not learned grasps or new demonstration data. A tiny pose-control probe requires contact-readiness checks; the original support and 6mm/6.5mm physical gates remain unchanged.

The diagnosis records the raw and normalized 81D actor inputs, original actor requests, interventions, wrapper clipping, joint bounds, guard corrections, applied targets and actual joint response before terminal resets. Original camera PNGs are preserved, and the frame ledger identifies profiles and episode boundaries. Delivery requires complete camera frames and exactly the declared profile videos: four for the original comparison or one for a single intervention. Evidence is written even on a partial or failed physical run; software execution and strict support scores remain separate results.

The main contact collector reads each Cube-to-body pair once per 2ms sample, then derives the seven finger and palm contributions with explicit force directions. It preserves raw normal/friction points and all support gates. The independent single-environment path compares 33 physical samples after first nonzero hand contact. Cube raw reporting capacity is 256 points per environment (increased from the initial probe's 32); reference hand capacity stays 32 points per body. This changes reporting capacity, not the physical contact solver. Terminal episode records transfer tensors in batches before formatting per-episode JSON.

- The historical controller called its rate 15 Hz but advanced 33 physics steps of 0.002 s per command. The configuration records the actual `500/33` Hz cadence separately. No timing change is hidden in the migration.
